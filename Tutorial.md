## 1. Graph Neural Networks

### What is a Graph?

A graph G = (V, E) consists of:
- **Nodes** V = {v_1, ..., v_M}: entities (in our case, lattice points)
- **Edges** E = {(v_i, v_j)}: connections (in our case, springs)

Each node can have a **feature vector** x_i (e.g., position coordinates).
Each edge can have a **feature vector** e_{ij} (e.g., spring constant, rest length).

### Why Not Just Use an MLP?

You could flatten all node/edge features into one big vector and feed it to an MLP.
Problems:
1. **Variable size**: Different graphs have different numbers of nodes. MLPs need
   fixed-size input.
2. **Permutation**: Nodes have no natural ordering. Reindexing nodes shouldn't change
   the prediction. An MLP would need to learn permutation invariance from data.
3. **No locality**: An MLP treats all features equally. But physics is local --
   a spring's contribution to the elastic tensor depends mainly on its neighbors,
   not on springs across the mesh.

GNNs solve all three by operating directly on the graph structure.

### The GNN Idea

A GNN updates each node's feature vector by aggregating information from its neighbors:

```
h_i^{(l+1)} = UPDATE( h_i^{(l)}, AGGREGATE({ h_j^{(l)} : j in N(i) }) )
```

where:
- h_i^{(l)} is node i's hidden state at layer l
- N(i) is the set of neighbors of node i
- AGGREGATE combines neighbor information (e.g., sum, mean, max)
- UPDATE produces the new hidden state (e.g., an MLP)

After L layers, each node's hidden state encodes information from its L-hop
neighborhood. A global READOUT function (e.g., mean over all nodes) produces
a graph-level prediction.

## 2. Message Passing Neural Networks

The most general GNN framework is the **Message Passing Neural Network** (MPNN):

```
m_{j->i} = MESSAGE(h_i, h_j, e_{ij})    # compute message from j to i
m_i      = AGG({ m_{j->i} : j in N(i) }) # aggregate messages
h_i'     = UPDATE(h_i, m_i)              # update node state
```

Different GNN architectures correspond to different choices of MESSAGE, AGG, UPDATE:

| Architecture | MESSAGE | AGG | Edge Features? |
|-------------|---------|-----|----------------|
| GCN | W * h_j / sqrt(deg_i * deg_j) | sum | No |
| GAT | alpha_{ij} * W * h_j (attention) | sum | No (in original) |
| GraphSAGE | W * h_j | mean | No |
| **NNConv** | **MLP(e_{ij}) @ h_j** | **mean** | **Yes -- generates weight matrix** |
| GIN | (1+eps) * h_i + sum(h_j) | sum | No |

For our problem, **edge features are the inputs** (spring constants, rest lengths).
NNConv is the natural choice because it lets edge features directly control the
message computation.

### PyTorch Implementation Pattern

```python
import torch
import torch.nn as nn
from torch_geometric.nn import MessagePassing

class SimpleGNN(MessagePassing):
    def __init__(self, in_channels, out_channels):
        super().__init__(aggr='mean')  # mean aggregation
        self.mlp = nn.Linear(in_channels, out_channels)

    def forward(self, x, edge_index):
        # x: (M, in_channels) node features
        # edge_index: (2, E) source and target for each edge
        return self.propagate(edge_index, x=x)

    def message(self, x_j):
        # x_j: features of source nodes for each edge
        return self.mlp(x_j)

    def update(self, aggr_out):
        # aggr_out: result of aggregation
        return aggr_out
```

## 3. Edge-Conditioned Convolution (NNConv)

NNConv (Gilmer et al., 2017) is the core building block of our GNN. It generates
a **different weight matrix for each edge** based on that edge's features.

### The Idea

In a standard linear layer: `output = W @ input`, where W is shared across all inputs.

In NNConv: `message_{j->i} = W(e_{ij}) @ h_j`, where W(e_{ij}) is a weight matrix
**generated by an MLP from the edge features**.

```python
# Edge neural network: maps edge features to a weight matrix
edge_nn = nn.Sequential(
    nn.Linear(edge_feat_dim, 128),
    nn.ReLU(),
    nn.Linear(128, in_channels * out_channels),  # outputs a flattened weight matrix
)

# For each edge (i,j):
W_ij = edge_nn(e_ij).reshape(in_channels, out_channels)  # (d_in, d_out)
message = W_ij @ h_j  # (d_out,)
```

### Why This Fits Our Physics

In the forward solver, each edge contributes to the elastic tensor via:
```
tensor_contribution_e = (k_e / l0_e^2 / 16) * geometric_factor(edge_vector)
```

The factor `k / l0^2` is a scalar weight that multiplies a geometry-dependent tensor.
NNConv mirrors this: the edge features `[k, l0, l_actual, log(k/l0^2)]` generate
a weight matrix that modulates the message from each neighbor. The network can learn
to extract `k/l0^2` from the features and use it appropriately.

### PyTorch Geometric Usage

```python
from torch_geometric.nn import NNConv

# Edge neural network: 4 edge features -> d_in * d_out weight matrix
edge_nn = nn.Sequential(
    nn.Linear(4, 128),
    nn.ReLU(),
    nn.Linear(128, 64 * 64),  # for a 64->64 layer
)

conv = NNConv(
    in_channels=64,
    out_channels=64,
    nn=edge_nn,
    aggr='mean',  # how to aggregate messages from neighbors
)

# Forward pass:
# x: (M, 64) node features
# edge_index: (2, E) edge connectivity
# edge_attr: (E, 4) edge features
h_new = conv(x, edge_index, edge_attr)  # (M, 64)
```

## 4. From Node Embeddings to Graph Predictions

After L message-passing layers, we have per-node embeddings h_i of dimension d.
To predict a graph-level property (like Poisson's ratio), we need a **readout**
function that aggregates all node embeddings into a single vector.

### Simple Readout: Mean Pooling

```python
from torch_geometric.nn import global_mean_pool

h_graph = global_mean_pool(h, batch)  # (batch_size, d)
# batch: (M,) integer tensor assigning each node to its graph in the batch
```

Problem: mean pooling loses distributional information. Two graphs with different
node embedding distributions but the same mean get mapped to the same vector.

### Better Readout: Set2Set

Set2Set (Vinyals et al., 2016) is an attention-based pooling that computes
a weighted sum, where the weights are learned:

```python
from torch_geometric.nn import Set2Set

pool = Set2Set(in_channels=64, processing_steps=6)
h_graph = pool(h, batch)  # (batch_size, 128) -- 2x input dim
```

Internally, Set2Set runs an LSTM for `processing_steps` iterations:
1. LSTM produces a query vector q_t
2. Attention: a_i = softmax(q_t^T h_i) over all nodes
3. Weighted sum: r_t = sum(a_i * h_i)
4. Output: concatenation of final q_T and r_T

This captures higher-order statistics of the node embedding distribution,
which matters for global properties like Poisson's ratio that depend on
correlations across the entire graph.

### Readout MLP

After pooling, a small MLP maps the graph vector to the prediction:

```python
readout = nn.Sequential(
    nn.Linear(128, 64),
    nn.ReLU(),
    nn.Dropout(0.1),
    nn.Linear(64, 32),
    nn.ReLU(),
    nn.Linear(32, 1),  # scalar output: Poisson's ratio
)

nu_pred = readout(h_graph)
```

## 5. Handling "No Node Features"

In many graph problems (molecules, social networks), nodes have intrinsic features
(atom type, user profile). In our spring networks, the physics lives entirely in the
edges (spring constants, rest lengths). Nodes are just lattice points with positions.

### Strategy: Construct Node Features from Geometry + Aggregated Edge Info

```python
def init_node_features(pos, edge_index, edge_attr):
    """
    Build node features from position and aggregated edge information.

    pos:        (M, 2) node coordinates
    edge_index: (2, E) edge connectivity
    edge_attr:  (E, feat_dim) per-edge features [k, l0, l_actual, log(k/l0^2)]

    Returns: (M, 8) node features
    """
    from torch_scatter import scatter_mean, scatter_std

    src, dst = edge_index  # (E,) each

    # Normalize positions to zero mean, unit std
    pos_norm = (pos - pos.mean(0)) / (pos.std(0) + 1e-8)

    # Degree: number of edges per node
    degree = torch.zeros(M, dtype=torch.float)
    degree.scatter_add_(0, src, torch.ones(E))
    degree.scatter_add_(0, dst, torch.ones(E))

    # Aggregate edge features to nodes (both endpoints)
    # For undirected edges stored once: scatter to both src and dst
    k = edge_attr[:, 0]       # rigidity
    l = edge_attr[:, 2]       # actual length
    f = edge_attr[:, 3]       # log(k/l0^2)

    # Mean and std of k at each node
    all_nodes = torch.cat([src, dst])
    all_k = torch.cat([k, k])
    all_l = torch.cat([l, l])
    all_f = torch.cat([f, f])

    mean_k = scatter_mean(all_k, all_nodes, dim=0, dim_size=M)
    std_k = scatter_std(all_k, all_nodes, dim=0, dim_size=M)
    mean_l = scatter_mean(all_l, all_nodes, dim=0, dim_size=M)
    std_l = scatter_std(all_l, all_nodes, dim=0, dim_size=M)
    mean_f = scatter_mean(all_f, all_nodes, dim=0, dim_size=M)

    return torch.stack([
        pos_norm[:, 0], pos_norm[:, 1],  # normalized x, y
        degree,                           # connectivity
        mean_k, std_k,                    # rigidity statistics
        mean_l, std_l,                    # length statistics
        mean_f,                           # physics-factor statistics
    ], dim=-1)  # (M, 8)
```

### Why This Works

After the first message-passing layer, each node already receives all edge features
from its neighbors. The hand-crafted initialization just gives the network a head
start -- it doesn't limit what the network can learn.

The position features (x, y) are important because the elastic tensor depends on
edge orientations, not just edge properties. Two springs with the same k and l0
but different orientations contribute differently to the tensor.

## 6. Variational Autoencoders (VAEs)

### The Problem VAEs Solve

We have a dataset of spring configurations {(k_1, l0_1), ..., (k_N, l0_N)} that
produce interesting elastic properties. We want to:
1. **Generate new** configurations similar to the training data
2. **Explore** the space of valid configurations smoothly
3. **Understand** what makes configurations similar or different

### Autoencoder Basics

An autoencoder compresses data through a bottleneck:

```
x  --->  Encoder  --->  z  --->  Decoder  --->  x_reconstructed
(input)            (latent code)             (output)
```

The bottleneck forces the model to learn a compact representation.
But a standard autoencoder's latent space is irregular -- you can't sample
random z vectors and get valid outputs.

### The VAE Fix: Regularize the Latent Space

A VAE forces the latent space to be "smooth" by making the encoder output a
**distribution** instead of a point:

```python
# Encoder outputs distribution parameters
mu, log_var = encoder(x)          # (batch, latent_dim) each

# Sample using reparameterization trick
std = torch.exp(0.5 * log_var)
eps = torch.randn_like(std)       # random noise
z = mu + std * eps                # differentiable sampling!

# Decode
x_recon = decoder(z)
```

### The ELBO Loss

VAE training maximizes the Evidence Lower BOund (ELBO):

```
L = L_recon + beta * L_KL
```

**Reconstruction loss** -- decoded output should match input:
```python
L_recon = MSE(x_recon, x)
# or binary cross-entropy for binary data
```

**KL divergence** -- encoder distribution should be close to standard normal:
```python
L_KL = -0.5 * torch.sum(1 + log_var - mu.pow(2) - log_var.exp())
```

The KL term prevents the encoder from ignoring the prior and collapsing to
delta functions. It ensures the latent space is smooth and that sampling
z ~ N(0, I) at inference time produces valid outputs.

### Reparameterization Trick: Why It's Needed

Sampling z ~ N(mu, sigma^2) is not differentiable (you can't backpropagate
through a random sample). The trick: rewrite sampling as a deterministic
function of mu, sigma, and external noise:

```
z = mu + sigma * eps,  where eps ~ N(0, I)
```

Now gradients flow through mu and sigma (but not eps, which is just noise).

### Beta Warmup

If you train with full KL weight from the start, the model collapses to
always outputting the mean (KL goes to zero, reconstruction is terrible).
Solution: start with beta=0 and linearly increase to 1 over the first
50 epochs. This lets the model first learn useful latent structure, then
regularize it.

## 7. Conditional VAEs (CVAEs)

### Conditioning on a Target

A standard VAE generates samples from the data distribution. A CVAE generates
samples **conditioned on a label** c (in our case, c = target Poisson ratio).

```python
# Training:
mu, log_var = encoder(x, c)     # encoder sees both data and condition
z = reparameterize(mu, log_var)
x_recon = decoder(z, c)         # decoder sees latent code and condition

# Inference:
z = torch.randn(latent_dim)     # sample from prior
x_generated = decoder(z, c)     # generate data for condition c
```

The condition c is typically embedded via a small MLP and concatenated or added
to the input of both encoder and decoder.

### Multi-Modality

The key advantage of CVAEs over regression: for the same condition c,
different latent codes z produce **different valid outputs**.

For our inverse problem:
- c = nu_target = -0.5 (desired Poisson ratio)
- z_1 -> one set of spring constants that produces nu = -0.5
- z_2 -> a completely different set that also produces nu = -0.5

This is exactly what we need: the inverse problem has many valid solutions,
and we want to explore them.

## 8. Graph VAEs: Encoding and Decoding Graphs

### Graph Encoder

The encoder uses the same GNN architecture as the forward surrogate, but
processes the full solution (graph + edge parameters + target):

```python
class GraphEncoder(nn.Module):
    def __init__(self, ...):
        self.gnn = GNNBackbone(...)      # NNConv layers
        self.pool = Set2Set(...)          # graph-level representation
        self.condition_embed = nn.Linear(1, 32)  # embed nu_target
        self.fc_mu = nn.Linear(pool_out + 32, latent_dim)
        self.fc_logvar = nn.Linear(pool_out + 32, latent_dim)

    def forward(self, data, nu_target):
        h = self.gnn(data)               # per-node embeddings
        h_graph = self.pool(h, data.batch)  # graph embedding
        c = self.condition_embed(nu_target)  # condition embedding
        combined = torch.cat([h_graph, c], dim=-1)
        return self.fc_mu(combined), self.fc_logvar(combined)
```

### Graph Decoder: Generating Edge Parameters

The decoder's job is unusual: given a graph topology (fixed), a latent code z,
and a target nu, it must output per-EDGE parameters (k, l0).

**Challenge**: z is a single vector (dim 32), but we need E different (k, l0) pairs.

**Solution**: Broadcast z to all nodes, then use GNN message passing to produce
node embeddings that are aware of z. Then for each edge (i, j), combine the
endpoint embeddings to predict that edge's parameters:

```python
class GraphDecoder(nn.Module):
    def __init__(self, latent_dim=32, hidden=64):
        self.z_project = nn.Linear(latent_dim, hidden)
        self.nu_embed = nn.Linear(1, hidden)
        self.geom_embed = nn.Linear(4, hidden)  # [x, y, degree, mean_length]

        # GNN using GEOMETRIC edge features only (not k, l0)
        self.gnn = GNNBackbone(edge_in=4)  # [l_actual, dx, dy, angle]

        # Per-edge output
        self.edge_mlp = nn.Sequential(
            nn.Linear(2 * hidden + 4, 128),  # [h_i, h_j, edge_geom]
            nn.ReLU(),
            nn.Linear(128, 64),
            nn.ReLU(),
            nn.Linear(64, 2),  # raw_k, raw_l0
        )

    def forward(self, data, z, nu_target):
        # Initialize nodes: geometry + broadcasted z + nu
        h = self.geom_embed(data.x_geom)
        h = h + self.z_project(z)[data.batch]    # broadcast z
        h = h + self.nu_embed(nu_target)[data.batch]  # broadcast nu

        # Message passing with geometric edge features
        h = self.gnn(h, data.edge_index, data.edge_geom)

        # Edge readout
        src, dst = data.edge_index
        edge_input = torch.cat([h[src], h[dst], data.edge_geom], dim=-1)
        raw = self.edge_mlp(edge_input)

        # Softplus for positivity (matching Phase 3 convention)
        k = F.softplus(raw[:, 0], beta=5.0)
        l0 = F.softplus(raw[:, 1], beta=5.0)
        return k, l0
```

**Key design**: The decoder GNN uses geometric edge features (actual length,
direction vector, angle) but NOT k or l0 -- those are the outputs, not inputs!
This forces the model to generate edge parameters from the latent code z and
graph geometry alone.

## 9. Physics-Informed Training

### The Problem with Pure Reconstruction Loss

Standard CVAE training: `L = L_recon + beta * L_KL`

The reconstruction loss matches predicted (k, l0) to true (k, l0). But we
don't actually care if the parameters match -- we care if they produce the
right Poisson ratio. Two completely different (k, l0) patterns can give the
same nu.

### Physics Loss

Add a term that evaluates the generated design through the forward model:

```python
# Decode edge parameters
k_pred, l0_pred = decoder(data, z, nu_target)

# Run through forward model (GNN surrogate or actual solver)
nu_pred = forward_model(graph, k_pred, l0_pred)

# Physics loss: does the design actually produce the target?
L_physics = (nu_pred - nu_target)**2
```

### Full CVAE Loss

```python
L_total = L_recon + beta * L_KL + gamma * L_physics
```

- **L_recon**: edge parameter matching (guides early training)
- **L_KL**: latent space regularization (enables sampling)
- **L_physics**: physical validity (the primary objective, gamma = 10)

### Two-Phase Training

The GNN surrogate is fast (~1ms) but has ~2% error.
The Phase 2 solver is exact but slower (~5ms) and memory-intensive.

Strategy:
- **Epochs 1-200**: Use GNN surrogate for L_physics (fast iterations)
- **Epochs 201-300**: Switch to actual solver for L_physics (refine accuracy)

This works because the GNN surrogate's gradient direction is correct even if
its absolute value has small errors. The final solver-based fine-tuning
corrects any systematic bias.

## 10. Complete Example: Forward Surrogate for Elastic Networks

Putting it all together -- a complete, runnable forward GNN surrogate:

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch_geometric.nn import NNConv, BatchNorm, Set2Set
from torch_geometric.data import Data, DataLoader


class ForwardGNN(nn.Module):
    """Predicts Poisson's ratio from a spring network graph."""

    def __init__(self, node_in=8, edge_in=5, hidden=64, n_layers=4,
                 pool_steps=6, dropout=0.1):
        super().__init__()

        # Input projection
        self.node_embed = nn.Linear(node_in, hidden)

        # Message-passing layers
        self.convs = nn.ModuleList()
        self.bns = nn.ModuleList()
        for _ in range(n_layers):
            edge_nn = nn.Sequential(
                nn.Linear(edge_in, 128),
                nn.ReLU(),
                nn.Linear(128, hidden * hidden),
            )
            self.convs.append(NNConv(hidden, hidden, edge_nn, aggr='mean'))
            self.bns.append(BatchNorm(hidden))

        # Global pooling
        self.pool = Set2Set(hidden, processing_steps=pool_steps)

        # Readout
        self.readout = nn.Sequential(
            nn.Linear(2 * hidden, 64),
            nn.ReLU(),
            nn.Dropout(dropout),
            nn.Linear(64, 32),
            nn.ReLU(),
            nn.Linear(32, 1),
        )

    def forward(self, data):
        x = data.x                  # (total_nodes, node_in)
        edge_index = data.edge_index  # (2, total_edges)
        edge_attr = data.edge_attr    # (total_edges, edge_in)
        batch = data.batch            # (total_nodes,)

        # Input projection
        h = self.node_embed(x)

        # Message passing with residual connections
        for conv, bn in zip(self.convs, self.bns):
            h_new = conv(h, edge_index, edge_attr)
            h_new = bn(h_new)
            h_new = F.relu(h_new)
            h = h + h_new  # residual connection

        # Global pooling
        h_graph = self.pool(h, batch)

        # Predict Poisson's ratio
        return self.readout(h_graph).squeeze(-1)


# --- Training loop sketch ---

def train_epoch(model, loader, optimizer, device):
    model.train()
    total_loss = 0
    for batch in loader:
        batch = batch.to(device)
        optimizer.zero_grad()
        nu_pred = model(batch)
        loss = F.mse_loss(nu_pred, batch.y_nu)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 5.0)
        optimizer.step()
        total_loss += loss.item() * batch.num_graphs
    return total_loss / len(loader.dataset)


@torch.no_grad()
def evaluate(model, loader, device):
    model.eval()
    total_mae = 0
    for batch in loader:
        batch = batch.to(device)
        nu_pred = model(batch)
        total_mae += (nu_pred - batch.y_nu).abs().sum().item()
    return total_mae / len(loader.dataset)
```

### Data Objects

Each graph is a `torch_geometric.data.Data` object:

```python
from torch_geometric.data import Data

data = Data(
    x=torch.randn(100, 8),          # 100 nodes, 8 features each
    edge_index=torch.randint(0, 100, (2, 300)),  # 300 directed edges
    edge_attr=torch.randn(300, 5),   # 5 features per edge
    y=torch.tensor([0.267]),          # graph-level label
)
```

`edge_index` is in COO format: `edge_index[0]` = source nodes, `edge_index[1]` = target nodes.
For undirected graphs, store each edge twice: (i->j) and (j->i).

### Batching

PyG batches multiple graphs into one large disconnected graph:

```python
from torch_geometric.loader import DataLoader

dataset = [data_1, data_2, ..., data_N]
loader = DataLoader(dataset, batch_size=64, shuffle=True)

for batch in loader:
    # batch.x: (total_nodes_in_batch, 8)
    # batch.edge_index: (2, total_edges_in_batch)
    # batch.batch: (total_nodes_in_batch,) -- which graph each node belongs to
    #   e.g., [0,0,0,..., 1,1,1,..., 63,63,63,...]
    pred = model(batch)  # works on the whole batch at once
```

The `batch` tensor is crucial: it tells pooling operations which nodes belong
to which graph. `global_mean_pool(h, batch)` computes the mean per graph.
