**A-15 · DOWNGRADED to hygiene (docs) + a prerequisite for the residual-stress program.
I over-stated this when I first logged it the same day; the measurement below is the correction.**
The oracle linearises the KINEMATICS — but that costs **nothing** for what the framework actually
computes. Model (1), linear springs with EXACT kinematics (U = ½Σk(‖xᵢ−xⱼ‖−ℓ₀)², relaxed by L-BFGS
on true bond lengths), is now implemented in `verification_tools/exact_kinematics_check.py`, and
against the linearised oracle the difference is **O(h) in the probe amplitude and vanishes as
h → 0**: 6.62e-3, 2.00e-3, 6.66e-4, 2.00e-4 at h = 1e-2, 3e-3, 1e-3, 3e-4. **The two models share a
tangent modulus.**

Why, and not by luck: at an unstressed reference (ℓ₀ = ℓ ⇒ bond tension T = 0) every term in
∂²U/∂ε² carrying second derivatives of ℓ is multiplied by δℓ = 0 and drops. A spring's tangent
stiffness is k·R̂⊗R̂ + (T/ℓ)(I − R̂⊗R̂); the GEOMETRIC term vanishes at T = 0, leaving exactly what
`assemble_K_faff` builds.

**So the current validation is sound for the current claims.** What survives:
  - *docs (real, already fixed):* §3 called the verification path a "nonlinear relaxation". False.
  - *the genuine gap — prestress.* At T ≠ 0 the geometric term survives, and `assemble_K_faff`
    **cannot represent it: it takes no rest-length argument at all** (ℓ₀ is implicitly |R|). So the
    oracle is structurally incapable of a prestressed tangent. This is exactly the incompatible-ḡ /
    residual-stress direction (FUTURE_DIRECTIONS #1), and it is the concrete reason behind §3's
    existing "flat-compatible only" caveat — which had been justified by "no δḡ" rather than by the
    missing geometric stiffness.
  - *near-mechanism*, where the tangent is nearly singular and any usable strain is dominated by
    what the tangent omits. Still unvalidated, but that is a scope limit, not a wrong number.

*Fix: none needed for today's results. Building a prestressed oracle (geometric stiffness + a
generalised virial) is a PREREQUISITE for the residual-stress program, not a repair of current work.*

**A-15 (as originally logged, over-stated) · the oracle is LINEAR, so "checked against the independent
simulation" cannot mean what CLAUDE.md §3 claimed it means.** Found 2026-08-15 while measuring
whether the solver and the sim agree. `physical_homog.relax` is a single `spsolve` of Ku = −f_aff
using the LINEARISED bond extension (R·δu)/ℓ — no iteration, no Newton, no minimisation — and a
repo-wide search finds **no geometrically nonlinear relaxation anywhere**. (Terminology: every model
here has a LINEAR Hookean constitutive law; "nonlinear" throughout means geometric/kinematic —
ℓ = ‖xᵢ−xⱼ‖ in the node positions — never a nonlinear material. The physical reference is
*linear springs with exact kinematics*, U = ½Σk(‖xᵢ−xⱼ‖−ℓ₀)², which is implemented nowhere.) §3 described the verification path as an
"independent NumPy periodic *nonlinear* relaxation"; that word was false and is now corrected.

Two consequences pull in opposite directions and both matter:

  - *Stronger than assumed where it applies.* Because both sides solve the SAME linear problem, the
    solver's own `forward()` matches the oracle to **1e-13 – 1e-11** on healthy disordered and VD

**A-17 REFINED 2026-08-17 (hexagon-diameter family) — there are TWO independent preconditions, and
the solver is EXACT whenever both hold.** The original entry below blamed "malformed triangulation";
that is one of two failure modes, and mesh-validity alone is **necessary but not sufficient**.

The controlled experiment (`Phase 5/verifications/hex_solver_validation.py`): one hexagon, six hard
perimeter edges of length 1, opposite-vertex separation `d` swept 0.2 → 2.8 (d=2 regular, d<1
re-entrant), triangulated two ways — **(a) 3 internal chords**, **(b) a centre vertex + 6 spokes**.
ν measured by pulling ⊥ to the diameter and reading along it, with the **identical** reduction applied
to solver and sim tensors (so A-10 cannot contaminate it).

| variant | d | inverted triangles | bond→#tri | solver-sim gap |
|---|---|---|---|---|
| chords | 0.20 | **8 / 32** | valid {2:48} | 8.6 |
| chords | 0.63 | **8 / 32** | valid {2:48} | 28.4 |
| chords | 0.85 | **8 / 32** | valid {2:48} | 26.6 |
| chords | 1.07 | 0 / 32 | valid {2:48} | **0.00000** |
| chords | ≥1.07 | 0 / 32 | valid {2:48} | **0.00000** |
| centre | ALL d | 0 / 48 | valid {2:72} | **0.00000** |

**The two preconditions.**
1. **Combinatorially closed** — every bond in exactly 2 triangles, V−E+F = 0. Violated by
   `square_octagon` {1:14,2:98,3:2}, `honeycomb`, `rotating_squares`, `reentrant_honeycomb`.
2. **Geometrically consistent** — no INVERTED (negative signed-area) triangles. Violated by the chord
   triangulation of a NON-CONVEX hexagon (d<1): the chord fan is a valid triangulation only of a
   convex polygon, so once re-entrant the triangles fold. Switches on exactly at d = 1.

They are independent: the chord meshes satisfy (1) and violate (2); the tilings satisfy (2) and
violate (1). **Either alone breaks the solver.** *Mechanism:* the metric formulation uses
`q_e = Δx Δxᵀ` and triangle areas, which are **orientation-blind** — a folded triangle is computed as
though correctly oriented. The nodal sim has only springs between nodes and is indifferent to both.

**Where the solver IS exact — and it is a strong list.** Gap **0.00000** with both conditions met,
including at **ν = −3.47** (deep re-entrant, variant b at d=0.2); across **8 orders** of stiffness
contrast on a valid mesh; the 9-family disorder sweep (1e-13…6e-08); ν=1/3, E=2/√3 on the crystal.
**Strong auxeticity is NOT the problem** — variant (b) reaches ν = −3.47 exactly.

**Neither condition is checked anywhere.** Both are cheap (a `Counter` over `tri_bond`; a signed-area
sign test on `tri_verts`). *NB compute signed area from `tri_verts`, NOT `pts` — under PBC the wrapped
coordinates produce spurious inversions, which is why an earlier check of mine wrongly dismissed
inversion as a "Delaunay orientation convention".*
